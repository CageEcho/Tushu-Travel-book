# 技术适配声明

> 阶段 1 产出。产品经理只需确认文末「三件事」，无需逐项看技术名词。

## 1. 产品形态判断
- 产品类型与核心任务：旅行工具 Web 端。用户粘贴小红书攻略链接 → 抓取正文+9 张图 OCR → 抽取地点（Day 分组+顺序）→ 人工确认 → 百度地图地理编码+路线编排 → 多途径点动线 + 跳转 App + 分享短链 + 长图导出。
- 核心交互：**分阶段确认**（粘贴→解析→人工确认关卡→生成动线），不是一次生成。
- 开发路径：**纵向切片（后端 + 极简验收页）**。原因：你产品里的「人工确认地点」和「亲眼看地图」本身就是核心体验，不能只看接口 JSON 判断好坏，所以需要一个能点、能看的极简网页来验收。但**不做正式前端**（正式前端留阶段 3）。
- 当前阶段范围：**M0 模块一最小闭环**（模块二/三暂不接）。

## 2. 采用的默认方案
- 后端语言：Python 3.12（本机已有 3.12.13，用 `python3.12` 建虚拟环境）
- 后端框架：FastAPI（把能力做成可测可调的接口）
- 数据校验：Pydantic（校验接口 + 模型结构化输出）
- 测试：pytest（mock 自动化测试）
- 模型调用：DeepSeek `deepseek-chat`（已实测通，用于地点抽取）
- 地图：百度地图 Web 服务 API（服务端 AK 已实测通：地理编码/地点检索/路线规划）
- 代码管理：Git（本阶段初始化仓库，`.gitignore` 已含 `.env`）

## 4. 偏离或暂缓的默认方案
- **Agent Plan（PRD 原主方案）→ 改用传统 Web 服务 API**：Agent Plan 内测 Token 未拿到；传统 API 已实测通、覆盖 M0 全部需求。影响：暂缺"语义化检索/语义路线"，靠「6 城约束 + 人工确认关卡」补偿。未来条件：拿到 Token 后作为增强项。
- **公网部署 / 分享短链外网可达 → 暂缓到阶段 4**（已定，必须问1=A）。
- **Python 版本**：本机默认 `python3` 是 3.9，改用 `python3.12` 建 `.venv`（与上线运行时一致）。

## 5. 强制底线检查
- 密钥与隐私：**通过**——百度 AK、DeepSeek key 已入 `.env`（gitignored），不入仓库/前端/日志，不回显。
- 数据与任务可恢复：**通过**——行程+任务状态存 SQLite，重启可恢复（开发期实测）。
- 输入输出校验：**通过**——Pydantic 校验接口；地点清单 schema 校验模型输出。
- 错误与日志边界：**通过**——统一错误结构 `{"error":{"code","message"}}`；日志不记密钥/完整用户文档。
- 测试与真实模型验收：mock 自动化测试（pytest）+ 真实冒烟（DeepSeek 抽取 + 百度 API 真实调用），按 AC-1.1/1.2 用真实样例验证召回率/POI 匹配率。
