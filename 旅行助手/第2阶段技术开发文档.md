# 第 2 阶段技术开发文档｜后端 MVP（M0 模块一最小闭环）

> 配套文档：`项目开发必备文件/旅行助手/PRD-旅行全流程助手.md`、AI Agent 产品 Vibe Coding 通用技术栈手册。
> 本文档只覆盖第 2 阶段（M0）。不得提前实现模块二/三、正式前端、公网部署。

## 一、阶段目标
- 交付范围：M0 最小闭环——粘贴小红书链接 → 抓取正文+图片 OCR → 抽取地点（Day 分组+顺序）→ 人工确认 → 百度地图地理编码+路线编排 → 多途径点动线（静态地图+跳转 App URI+分享短链+长图导出）。
- 阶段产物：后端 API + 极简验收页（`backend/app/static/index.html`）+ mock 测试 + 真实冒烟 + 证据包。
- 验收标准（对齐 PRD AC-1.x）：召回率≥80%（16 景点抽到≥13）、POI 匹配≥70%（≥11）、确认前不生成动线、动线可渲染+可跳转 App、分享只读。
- 明确不做：模块二/三、JSAPI GL 内嵌地图（阶段3）、公网部署、登录。
- 主链路片段：`POST /trips` → 后台流水线（抓取→OCR→DeepSeek 抽取→百度地理编码）→ `GET /places` 人工确认 → `POST /route` 百度路线编排 → `GET /route` 动线 + 跳转 App + 分享 + 长图。

## 二、技术适配摘要
- 采用：Python 3.12 + FastAPI + Pydantic + pytest + SQLite(SQLAlchemy) + DeepSeek + 百度 Web 服务 API。
- 启用按需模块：PaddleOCR（本地中文 OCR）、SQLite、Playwright（长图导出）、requests（小红书抓取，快照兜底为主）。
- 偏离/暂缓：Agent Plan → 传统 Web 服务 API；SSE → 提交+轮询；正式前端 → 单 HTML 验收页。
- 开发路径：纵向切片（后端 + 极简验收页）。

## 三、技术栈与模型
- 后端：Python 3.12、FastAPI、Uvicorn、SQLAlchemy、Pydantic v2、python-dotenv、httpx、openai（DeepSeek 兼容）、requests、Pillow、Playwright。
- 模型：DeepSeek `deepseek-chat`（`DEEPSEEK_BASE_URL=https://api.deepseek.com`），用于地点结构化抽取。
- 不引入：Alembic（MVP 用 create_all + schema 版本号）、Redis/任务队列、Next.js。

## 四、环境与配置
- `.env`（已建，gitignored）：`BAIDU_MAP_AK`、`DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL`、`DEEPSEEK_BASE_URL`。`.env.example` 不含秘密。
- 启动端口：`8000`。依赖：本机 Python 3.12 venv；Playwright Chromium（长图导出用，按需 `playwright install chromium`）。

## 六、数据、资产与状态
- 持久化：SQLite `data/tripflow.db`（SQLAlchemy），meta 表存 `schema_version=1`。
- `Trip`：id(短码，兼分享码)、source_link、note_id、title、city、status、created_at、updated_at。
- `Place`：id、trip_id、day、seq、name、type、source_text、confirmed、poi_name/poi_uid/poi_address、lat/lng、geocode_status、candidates(JSON)、skipped。
- `Task`：id、trip_id、kind(parse/route/export)、status(pending/running/done/failed)、progress、error、result_path、created_at、updated_at。
- 状态机（trip.status）：`created → parsing → awaiting_confirm → routing → done`；任一步失败 → `failed`。重启后：`running` 任务置 `failed`（可重新提交）。
- 资产：OCR 临时图、长图导出 PNG 存 `data/assets/{trip_id}/`。

## 七、API / 工具设计
统一前缀 `/api/v1`；错误结构 `{"error":{"code","message"}}`；长任务用「提交+轮询」。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | /trips | body `{source_link}` → `{trip_id, task_id}`，启动后台流水线 |
| GET | /trips/{id} | 行程摘要+状态 |
| GET | /trips/{id}/task | `{status, progress, error}` |
| GET | /trips/{id}/places | 地点清单（含候选 POI） |
| PATCH | /trips/{id}/places/{pid} | 改名/换 POI/调序/勾选/跳过 |
| POST | /trips/{id}/route | 确认后启动路线编排 → `{task_id}` |
| GET | /trips/{id}/route | 逐天动线（分段交通方式+耗时）+ 静态地图 URL |
| GET | /trips/{id}/app-nav | `{max_via, uris, days:[{day, legs:[{leg, from_place, to_place, via, uri, web_uri, web_basic_uri}], segments:[{from_place, to_place, transit|walking|riding:{uri, web_uri}}]}]}`（legs=驾车含途经点；segments=公交/步行/骑行逐段）（baidumap:// 唤起，途经点走 `viaPoints`，每段超 `BAIDU_NAV_MAX_VIA` 个自动拆段） |
| GET | /share/{trip_id} | 只读分享数据 |
| GET | /trips/{id}/map | 静态地图 PNG |
| POST | /trips/{id}/export | 启动长图导出 → `{task_id}`；完成后取文件 |

## 八、Prompt 设计
- `services/prompts/extract.txt`：角色=从 OCR 文字抽取旅行地点清单；输入=城市、OCR 文本；输出=严格 JSON `{places:[{day,seq,name,type}]}`；约束=只保留 6 城内景点、保留原始出现顺序、Day 分组与原文一致；给正反例。
- 解析：DeepSeek 输出 → 后端宽容解析 JSON → Pydantic 强校验；失败有限重试（≤3），仍失败回退快照地点。

## 九、验收界面或纵向切片
- 单 HTML（`backend/app/static/index.html`）：粘贴链接 → 看解析进度 → 确认/纠正地点 → 生成动线 → 看静态地图 + 跳转 App 按钮 + 分享 + 导出长图。是临时验收工具，阶段 3 用正式前端替换。

## 十、测试要求
- 第一层 mock（pytest，模型/网络全 mock）：抽取解析器纯函数（正/反例、宽容解析、校验失败回退）、状态机流转、确认前禁止生成动线、分享只读、错误统一结构、schema 校验、快照数据完整性（16 景点 Day/seq 正确）。
- 第二层真实冒烟：demo 链接 → 真实 DeepSeek 抽取（记录召回率 vs 16、重试前后合规率）+ 真实百度地理编码（记录 POI 匹配率）+ 真实路线编排；记录耗时/成本。
- 数据恢复：进程重启后 trip/task 状态可读、running 置 failed。
