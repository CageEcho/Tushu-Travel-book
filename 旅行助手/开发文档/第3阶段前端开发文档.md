## 3. 运行和职责

开发：浏览器访问 Vite 5173，`/api` 代理到已有后端 8000，便于实时预览。分享页面由同一版前端处理；现有 Vite `/share` 代理可能让开发时打开后端旧构建，应一并校正。

前端负责输入、状态、人工编辑、地图展示与下载入口；后端负责模型调用、地理编码、路线、任务和数据保存。前端不直接调用 DeepSeek 或使用服务端地图 AK。

配置注意：后端代码默认加载的是 `旅行助手/.env`，其次 `旅行助手/backend/.env`，不是仓库最外层 `.env`；当前进程也可能使用已注入的环境变量。联调时检查来源，不复制或输出密钥。

## 4. 当前真实接口

统一前缀 `/api/v1`。下表以代码为准。

| 用户操作 | 接口 | 请求或结果 |
| --- | --- | --- |
| 提交攻略 | POST `/trips` | `{source_link}` → `{trip_id, task_id}`，201 |
| 恢复行程 | GET `/trips/{id}` | 行程信息与 `status`；当前没有可恢复的 task ID |
| 查询任务 | GET `/tasks/{task_id}` | `kind/status/progress/error/result_path`；progress 是文字，不是百分比 |
| 获取地点 | GET `/trips/{id}/places` | 标题、城市、状态与 places，含候选 POI |
| 保存修改 | PATCH `/trips/{id}/places/{pid}` | 名称、day、seq、POI、坐标、skipped 等；当前只允许 awaiting_confirm |
| 人工确认并生成 | POST `/trips/{id}/route` | 无请求体 → `{trip_id, task_id}` |
| 查看动线 | GET `/trips/{id}/route` | 按天 places、segments、map_url |
| 静态地图兜底 | GET `/trips/{id}/map?day=N` | image/png |
| 导航 | GET `/trips/{id}/app-nav` | `{max_via, uris, days}`，含驾车 legs、逐段导航 segments |
| 分享数据 | GET `/share/{id}` | `{trip, places, route}` |
| 生成长图 | POST `/trips/{id}/export` | `{trip_id, task_id}`；完成后再允许下载 |
| 下载长图 | GET `/trips/{id}/export.png` | PNG 文件；不直接使用任务中的本地 result_path |

旧后端文档的 `/trips/{id}/task` 并不存在；导航也已从旧文档的单个 `{uri}` 演进为分天分段结构。

同步 API 错误为 `{"error":{"code","message"}}`。前端应保留错误码并归一化展示。异步 task.error 当前是字符串，需在后端转换成安全的用户消息，避免将供应商原始异常直接展示。

## 5. 状态与恢复方案

| 后端事实 | 页面表现 | 恢复原则 |
| --- | --- | --- |
| 尚无行程 | 输入页 | 保留输入；提交时阻止按钮、回车、demo 入口重复触发 |
| created / pending | 已受理 | 查同一个任务，不重新提交 |
| parsing / running(parse) | 正在解析与定位 | 显示后端 progress |
| awaiting_confirm | 等待人工确认 | 恢复服务器保存的地点、顺序和分天 |
| routing / running(route) | 正在生成路线 | 锁定编辑；继续查原任务 |
| done | 动线结果 | 拉取路线、导航与已有产物 |
| running(export) | 长图生成中 | 保留路线结果，独立显示导出状态 |
| failed | 可理解的失败提示 | 保留已有结果；重试必须匹配后端允许的状态 |
| 网络中断 | 连接中断、正在恢复 | 不把网络错误当作任务失败 |
| 无效 ID / 未知状态 | 不存在或暂无法识别 | 不静默跳到确认页或成功页 |

推荐补充后端按行程返回最新 parse/route/export 任务摘要，避免只保存 task ID 于浏览器内存。URL 保留 trip ID，刷新后查询后端事实并恢复轮询。GET 使用有限重试、退避和请求超时；POST 超时不自动重复创建，需先核对原任务。

后端重启目前会把 pending/running 任务标记 failed，但没有同步修正 trip.status。应一并修正；“恢复”表示结果仍在且中断可识别，不代表后台工作能自动续跑。

## 6. 已发现的衔接差异与建议

| 差异（代码核对） | 影响 | 推荐处理 |
| --- | --- | --- |
| `/share/{id}` 在前端仍走普通编辑页面，未调用专用分享 API | 分享并非独立只读体验 | 拆出分享展示模式，使用分享 API；后端也需区分编辑凭证与分享标识，不能只藏按钮 |
| 当前无编辑鉴权，trip ID 同时是分享 ID | 得到分享 ID 可尝试写接口 | 在无登录前提下设计最小编辑凭证；新旧行程兼容和领取方式在实现前明确，保留原数据 |
| 刷新时不判断 trip.status，直接进入 confirm | 运行中行程会显示错误阶段 | 增补任务查询信息，按真实状态恢复 |
| “调整地点”只改前端 phase，PATCH 拒绝 done | 结果页回到编辑后保存失败 | 增加明确的回到编辑步骤，保留上次成功结果，标记旧路线/长图需重新生成 |
| 缺少排序控件，分天只有 Day1/Day2 | 与 PRD 的排序、分天不一致 | 接入 day/seq，提供拖动及键盘可用的移动操作，分天按实际数据渲染 |
| 地图以地点坐标直接连线 | 这是地点顺序示意，不是道路级导航轨迹 | 界面明确“地点顺序示意”；实际导航使用后端下发的导航链接，不宣称画出了真实道路轨迹 |
| 地图加载从 index.html 引入，config.ts 未被 MapView 使用 | 文档所写配置入口失效 | 统一配置入口；确认现有 AK 的应用类型和访问限制，失败时显示真实静态图 |
| API 层无超时、无运行时结构检查，任务轮询无退避 | 断网或响应异常体验不稳定 | 集中补齐，轮询终止态停止，切换行程清理旧请求 |
| 生成请求缺少完整防重复约束 | 回车、demo 和重复 POST 可能产生额外任务 | 前端统一提交锁；后端为任务创建增加幂等/并发保护 |

地图导航沿用已合入的 viaPoints 方案，由后端下发链接。电脑展示二维码与网页入口；手机尝试唤起 App。手机联调需可访问的电脑局域网地址，localhost 二维码不算手机验证成功。网页版含途经点的兼容性、App 真机行为均待本轮实测。
